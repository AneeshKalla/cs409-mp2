explain what controller does and why tehres a timeout in the effect that does API calls and how that works







2:16 AM






controller lets us cancel an API request when it’s no longer needed:
const controller = new AbortController()
We connect it to Axios using its signal:
await api.get('/search/movie', {
  params: { query },
  signal: controller.signal,
})
Calling controller.abort() cancels that request. This matters when you type another character or leave the page: an old request shouldn’t update the screen after a newer search.
The setTimeout waits 300 milliseconds before making the request:
const timer = setTimeout(async () => {
  // Make API calls here
}, 300)
That’s called debouncing. Instead of requesting movies for every keystroke, we wait until you briefly stop typing.
For example, typing bat quickly:
1. You type b: a 300 ms timer starts.
2. You type a: React cleans up the previous effect, cancels its timer, and starts a new timer for ba.
3. You type t: the same thing happens for bat.
4. You stop typing for 300 ms: the request for bat runs.
The cleanup handles both possibilities:
return () => {
  clearTimeout(timer)
  controller.abort()
}
- clearTimeout(timer) cancels the scheduled call if it hasn’t started yet.
- controller.abort() cancels the request if it has already started.
React runs that cleanup before rerunning the effect when its dependencies change, and when the component is removed.
Finally, this check:
if (!controller.signal.aborted) {
  setError('Could not load movies...')
}
prevents intentional cancellations from displaying an error. We also use it before setLoading(false) so a canceled request doesn’t turn off the loading indicator for a newer request.

React Router shows different React components based on the URL without reloading the whole page.
In your app:
- / → movie search
- /gallery → poster gallery
- /movie/550 → details for movie 550
<Route> connects a URL to a component, and <Link> lets users navigate between those URLs.
